## 1. Словарь — простым языком

Одно значение на слово на весь проект; второго не заводить.

| Слово | Что это | Пример |
|---|---|---|
| **Токен** | Имя для числа или краски. Имя живёт долго, число под ним меняется | `--pad-card` вместо `24px` |
| **Примитив** («сырьё», склад) | Всё, что вообще разрешено: все оттенки, все шаги отступов, все кегли — без ответа «для чего» | `--space-6: 24px` |
| **Роль** («должность») | Токен по назначению: указывает на примитив и говорит, где работает. Экраны читают роли. Тема, страна и тёмный режим меняются здесь | `--content-strong`, `--pad-card` |
| **Узел** | Кнопка, поле, карточка, шапка. Читает роли, чисел не знает | кнопка «в корзину» |
| **Ярусы** | Этажи: сырьё → роли → узлы. Ссылки только вниз | `.card { padding: var(--pad-card) }` |
| **Тема** | Другой бренд или страна: свои краски и шрифт при тех же ролях | cbdshop.hr и cbdin.ro на одном коде |
| **Режим** | Светлое/тёмное; палец/курсор — столбцы значений у ролей | тёмная тема; «под пальцем 44» |
| **Ось** | По каким обстоятельствам у роли разные значения: тема, указатель, рынок | |
| **Поля** (inset) | Пустота **внутри** коробки: от края кнопки до надписи. Как паспарту у фото | поле карточки 24 |
| **Воздух** (stack, gap) | Пустота **между** вещами: между блоками, между карточками. Ставит родитель (`gap`), не ребёнок (`margin`) | 88 между полосами |
| **Ритм** | Расстояния повторяются: один шаг воздуха на все полосы. Получается сам, если все берут из одной линейки | |
| **Шкала** (линейка) | Короткий разрешённый список чисел. Сдержанность списка делает сайт цельным | 4, 8, 12, 16, 24, 32, 48, 64 |
| **Клетка** (база) | Одно памятное число, от которого считают всё: 4 или 8 | у нас 4 |
| **Рампа** (clamp) | Число, плавно меняющееся между двумя названными ширинами: столько на телефоне, столько на макете | `clamp(48px, …, 88px)` |
| **Шов** (breakpoint) | Названная ширина, на которой раскладка меняется скачком. Мало, с именем и причиной, в реестре | 860 |
| **Контейнерный запрос** | Узел меряет ширину **своей** коробки, а не окна | `@container (width >= 400px)` |
| **Цель нажатия** | Область, куда попадает палец; больше значка. 44 по меньшей стороне | значок 20 в кнопке 44 |
| **Контраст** | WCAG: 1…21 (4.5 : 1 текст, 3 : 1 крупный и рамки). APCA: Lc (60 подписи, 75 текст, 90 мелкий) | |
| **Тон** (L*) | Светлота по восприятию, 0 чёрный — 100 белый. Контраст решает разница тонов | ΔT ≥ 50 ⇒ 4.5 : 1 |
| **Этаж** (surface) | Кто над кем: страница, карточка, шторка. В тёмной — светлотой, не тенью | |
| **Состояние** | Как выглядит нажимаемое под курсором, пальцем, клавишей, выключенное. Один ответ на всех | `pressable` |
| **Слепок** | Машинная копия токенов, которую показывает админка и сверяет тест | `design-snapshot.mjs` |
| **Сторож** | Тест, который краснеет, когда правило снимают | `token-layer.test.ts` |
| **Мера строки** | Сколько знаков в строке абзаца: 45–75 | `max-inline-size: 60ch` |
| **Составной токен** | Несколько значений, которые ездят вместе: шрифт + кегль + высота строки + вес | роль текста «тело» |

Не смешивать: «примитивы» у Atlassian — кирпичи раскладки (Box, Stack,
Inline); у нас — сырьё палитры и шкал. «Тема» у Figma — то же, что у нас
«режим».

## 2. Порядок слоёв — на чём сходятся профессионалы

Ни один каталог не нумерует шаги (навигация у всех алфавитная). Порядок
выведен из четырёх независимых признаков, и они сходятся: **граф
зависимостей пакетов** (Carbon: `@carbon/themes` ← `@carbon/colors`,
`@carbon/type` ← `@carbon/layout`), **направление ссылок токенов** (DTCG: узел →
роль → примитив), **порядок подключения к живому проекту** (Atlassian, Carbon:
сброс + словарь → тема на корне → компоненты → замена сырых значений →
проверка целой страницы), **порядок слоёв CSS** (ITCSS: settings → tools →
generic → elements → objects → components → trumps; CUBE: tokens → composition
→ utility → block → exception) — от общего и дешёвого к частному и дорогому.
Atomic Design добавляет второе измерение: строить снизу вверх, **проверять
сверху вниз непрерывно** — слой не закрывается в отрыве от живой страницы.
**СИЛЬНО.**

**Порядок страниц** (Baymard, по воронке покупателя; УМЕРЕННО): главная и
раздел → список товаров с фильтром → страница товара → корзина → оформление.
Не «всё сразу вперемешку».

**Где спорят:**

- *Типографика до пространства или после?* Material, Apple, Tim Brown — шрифт
  раньше; Carbon, Spectrum, Atlassian — отступы раньше; Utopia и Every Layout
  выводят пространство **из кегля**; Curtis — база и лесенка, потом
  типографика, потом размер. Разрешение (слой 4): два числа кегля тела —
  телефон и макет — записываются первыми, и от них считаются и линейка, и
  лестница. Тогда 5 → 6 не спорит с 6 → 5.
- *rem или px?* Carbon, Tailwind, Utopia, Every Layout — rem; Atlassian,
  Spectrum, Primer **авторят в px** (Primer выпускает rem, Atlassian — rem на
  выходе); Radix — px × множитель. Довод за rem: покупатель, поднявший шрифт
  в браузере, получает крупные буквы в прежних полях (WCAG 1.4.4). Довод за
  px (агент по линтерам): сетка обязана оставаться жёсткой при увеличении
  текста, а не плыть; Josh Comeau (частично): rem — для отступов, служащих
  чтению (поле вокруг текста, между абзацами), px — для того, что не должно
  расти с текстом. Разрешение — §3.5.
- *Роли для отступов — нужны ли?* Radix, Tailwind, Atlassian, Utopia, Carbon
  ролей **не поставляют** (Carbon завёл вторую шкалу `layout-01…07` для
  воздуха между блоками и **отменил её** обратно в единую: «do not use in new
  work»); Curtis, Primer, Spectrum — роли по работе (`stack.gap`,
  `control.paddingInline`, `component-edge-to-text`). Разрешение: одна
  шкала-примитив; роли — **семейства имён по работе**, а не вторая шкала
  чисел; роль заводится там, где расстояние повторяется у разных узлов
  (правило трёх), единичному узлу — своё свойство, привязанное к ступени.

## 2.1. Сверка дайджеста с сырыми ответами (20.09.2026)

По слову заказчика «даже сами эти шаги ты взял, не усомнившись, или
проверил по исследованиям?» — §2 и §3.2–3.3 сверены с `raw/findings/`
построчно. Что подтвердилось и что поправлено:

- **Порядок слоёв — синтез, а не стандарт.** Ни один из девяти ответов
  `site-steps/` не даёт двадцати слоёв 0–19; ближайший — Material / Apple
  (13 слоёв, почти 1 : 1 с нашими 0–13). Четыре ответа сами оценивают
  порядок как «средний, выведен мной». Метка §2 для ПОРЯДКА — **УМЕРЕННО**;
  СИЛЬНО — сами принципы (граф зависимостей, направление ссылок, семь
  пунктов согласия по пространству).
- **Два спора не были записаны.** Atlassian ставит Spacing раньше Color,
  Spectrum — Color раньше Spacing; Practical UI — Colour раньше Layout,
  Refactoring UI — после Hierarchy и Spacing. Наш путь «цвет первым»
  совпадает с Practical UI и Spectrum; Refactoring UI добавляет слой,
  которого в таблице нет: **иерархия — что важнее чего** («не только
  увеличивать важное, но и специально приглушать неважное»). Он входит в
  слой 0 как характер и в слой 6 как роли текста.
- **Пример ролей Spectrum `component-edge-to-text-*` устарел**: в снимке
  токен помечен deprecated и переименован в `base-padding-horizontal-medium`
  (12 на десктопе / 15 под пальцем — то же 1 : 1.25). Живой пример ролей по
  работе — Primer `control.paddingInline`, `stack.gap`.
- **Замер люкса цитировался выборочно.** Коридор ×1.33…1.5 — про воздух между
  разделами (Muji ×1.35, Glossier ×1.33, Diptyque ×1.4); сырой ответ называет
  и выбросы: шапки ×1.36…1.74, край Byredo ×1.75, зазоры сеток ×2…3. Тело
  Byredo и Muji на 1440 — 14, не 13. Поэтому у порогов два коридора
  (`tools/thresholds.mjs`, `AIR.growth`). И: 375 нет в первой шестёрке ширин
  ни у Румынии, ни у Хорватии (393, 384, 414, 360) — замер на рыночных
  ширинах впереди.
- **Utopia 2.5×** — с условием `maxWidth < 5·minWidth`; прогон 16 → 40
  проходит, 16 → 41 падает на 1395–1690px.
- **44 под палец — не из Vercel WIG**: в прочитанном тексте числа нет;
  источник — WCAG 2.5.5 / 2.5.8, Apple, Material, Primer `minTarget`.
- **Числа, которых в §2 не было, а в сырых ответах есть**, теперь стоят в
  `tools/thresholds.mjs` и в `scale/references/build.md`: M3 Major Second
  от 14; Spectrum 1.125 от 14 / 17; Carbon `spacing-01…13`; rhythmguard
  `rhythmic-4`; Atlassian ярусы 0–8 / 12–24 / 32–80; межстрочье Butterick

**На чём сходятся (СИЛЬНО):**

1. **Одна линейка, короткая, от клетки 4 или 8.** Шагов больше у базы, меньше
   вдали (Tailwind: шаг 2 между 12 и 16, дальше 4, выше 64 — 8; Radix: +4, +8,
   +16). Ступень — по просителю. Ниже 8 — доводка, не ступень (порог
   `SPACING_FLOOR = 8` у нас уже есть); единственное признанное отступление —
   «волосок» ≤ 1 px под рамку.
2. **Поля и воздух — разные обязанности, одна шкала.** Carbon буквально
   отменил вторую шкалу для воздуха. Промежуток ставит **родитель** (`gap`; Every
   Layout — `* + *`), не ребёнок.
3. **Ширины — своя шкала.** Контейнер, колонка, швы не выводятся из базы
   отступов; **высоты целей** — тоже своя семья (Carbon `container-*`, наши
   `--control-*` — верно).
4. **Сырое число в `padding`/`margin`/`gap` — ошибка сборки**, не замечание.
5. **Отрицательный отступ — обратная сторона положительного**, та же
   переменная (Radix Inset).
6. **Плотность не меняется сама по ширине** (Material, Apple); если меняется
   — то по имени (Primer) или по оси указателя (Spectrum), а не «на глаз».
7. **Один авторский источник → всё остальное генерируется** (Carbon DTCG →
   scss/js/d.ts; Primer JSON5 → CSS; Utopia — калькулятор): числа не пишут
   руками в трёх местах.

### 3.3. Что это значит для «минимализма-лакшери»

Воздух — главный рычаг дорогого вида, и это записано у Material («low
density — for sites where aesthetics and focus matter») и Apple («брендинг
уступает содержимому»); Refactoring UI: **начать с избытка воздуха и убирать**,
не наоборот; **не всё тянется на всю ширину**; **тень вместо линии**, меньше
рамок. Профессиональный ход — не больше ступеней, а больший разрыв между
«внутри узла» и «между блоками»; ступеней меньше.

Число — снимается, а не назначается. **Замер живых магазинов** (Playwright,
`getComputedStyle` на отрендеренной странице, 20.09.2026, на 375 и 1440;
Aesop, COS, Arket, Jo Malone, Tom Ford, Net-a-Porter закрыты анти-ботом —
не вошли; измерены Apple Store, Le Labo, Byredo, Diptyque, Muji US, Cuyana,
Glossier; `raw/findings/space/pro_luxury-measured.json`). УМЕРЕННО — семь
сайтов, две ширины:

- **Воздух между полосами больше поля карточки в 3–5 раз**, а не равен ему:
  Muji 44 : 17 на 375 (2.6 : 1) и 60 : 17 на 1440 (3.5 : 1); Glossier — явный
  блок-спейсер 60 / 80 против промежутка сетки 12 / 16 (5 : 1 на обеих
  ширинах). Роли `--air-*` и `--pad-*` — с заведомо разным множителем.
- **База текста у «тихого люкса» часто меньше 16**: Byredo 13 / 20, Cuyana
  13 / 20, Muji 13.1 / 15.1, Le Labo 14 / 18.2; только Apple 17 / 25 и
  Glossier 16 / 18.4. «Дорого» держится воздухом вокруг умеренного кегля, а
  не кеглем.
- **Край страницы и отступ читаемой колонки — разные величины**: у Diptyque
  край 12 на обеих ширинах, отступ первого абзаца 32 → 394; у Muji край 10,
  отступ заголовка 19 → 288. Две роли: `--page-edge` (малая константа
  10–16, держит фото впритык к краю) и ширина/отступ колонки чтения.
- **Одна и та же роль между 375 и 1440 растёт в 1.33–1.5 раза**: секции Muji
  ×1.36, спейсер Glossier ×1.33, шапки Cuyana ×1.36 и Byredo ×1.5, поле
  карточки Byredo ×1.33, секция Diptyque ×1.4. Ориентир для рамп:
  max / min ≈ 1.35, а не произвольный скачок. Наш `--layout-band-pad`
  48 → 88 (×1.83) — щедрее всех измеренных.
- **Почти все числа кратны 4, большинство — 8** (84/56/16/28/44/12; 60/80/12/16;
  50/68/12; 208/40/48/44) — общая клетка при несовпадении ни одного значения.
- Четыре из семи — Shopify OS 2.0: воздух полосы там — отдельный пустой блок
  или настройка секции, **которую правит владелец** (то же, что наш слот
  ритма в админке).
- Что не копировать: сами px (они ниже по потоку от чужой типографики и
  ширины колонки); 208 у Apple — это (1440 − 1024) / 2, побочный эффект их
  `max-width`; «плавная функция» из двух точек не доказана — нужна третья
  ширина (1024).

Оговорка Baymard (бенчмарк 7 люкс-сайтов): минимализм хорош на главной и
странице товара, но **не оправдывает урезание поиска и фильтров** — там люкс
провалился («Poor»).

### 3.4. Предлагаемое устройство слоя (на решение владельцу)

Зеркально цвету — три яруса, ни одного второго словаря:

1. **Примитивы — общая шкала `--space-*` пакета остаётся единственной** и не
   переопределяется в витрине (кормит геометрию общих узлов — 941 чтение). В
   заголовке — основание: клетка 4, ступени по просителю, ниже 8 — доводка.
   Один авторский источник (JSON/TS) → `primitives.css` + слепок админки, как
   уже делает `design-snapshot.mjs`.
2. **Роли — семейства по работе, в отдельном разделе `semantic.css` (или
   `spacing.css` между `primitives` и `base`)**: `--pad-*` (поля внутри:
   `--pad-card`, `--pad-control`, `--pad-field`, `--pad-sheet`; squish/stretch
   — поименованное отклонение с коэффициентом из макета), `--air-*` (воздух
   между: `--air-band`, `--air-head`, `--air-block`, `--air-line`), `--gap-*`
   (в ряду и сетке: `--gap-grid`, `--gap-chips`, `--gap-targets` — зазор
   между целями, растёт под палец). Первая витрина получает роли **с нулевым
   сдвигом** — как 21 роль цвета 26.08.2026, с арифметическим доказательством
   скриптом.
3. **Слой витрины переобъявляет роли, а не шкалу.** `apps/storefront3` ставит
   свои `--air-*`, `--pad-*`, `--gap-*`, свой холст, колонку, поле от края
   (отдельно от промежутка сетки), свои швы — числами «лакшери» с причиной в
   заголовке файла, как в `Icons.tsx`. Общие узлы настраиваются крючками
   (`--band-pad-*`, `--cta-pill-pad`, `--field-pad`, `--rail-gap`).
4. **Рампа принадлежит роли, а не месту**: `clamp(число телефона, px + vw,
   число макета)` по одной формуле через две названные ширины (320 и свой
   холст); концы — ступени; пары «через ступень» — воздуху и герою, «одна
   ступень» — полям. Внутри узла — от `cqi`, не от `vw`.
5. **Плотность** — не глобальный множитель, а **имя** (Primer condensed /
   normal / spacious) или **ось указателя** (Spectrum `sets`): цель 44 и зазор
   16 под пальцем, 16 и 8 под курсором — одна переменная, значение по
   `@media (pointer: coarse)`. Множитель Radix — только по запросу владельца,
   с закрытым списком, что масштабируется.
6. **Швы третьей витрины — свой реестр** той же формы `LayoutSeam`; в общий не
   пишутся. Начальный набор — с её частей, не 860/1439.
7. **Админка — выбор ступени, не печать длины**: слот предлагает ступени/роли
   из списка либо пару «телефон / макет»; не появляется у магазина, чья
   витрина его не слушает (капкан Geist). Сегодняшний слот кладёт `72px`
   поверх рампы — телефон теряет пол 48.
8. **Сторожа тем же заходом, каждый проверен обратным ходом:**
   (а) `lint:css` — глоб на `app/`; `declaration-strict-value` на
   `margin`/`padding`/`gap`/`inset` (разрешены `var()`, `0`, `auto`,
   `calc(var() ± 1px)`); `rhythmguard/use-scale` с `scale: "auto"` из
   `primitives.css` — линтер читает шкалу из файла, а не помнит её;
   `property-layout-mappings: flow-relative` (логические свойства — родное
   правило stylelint, плагин `use-logical` в режиме поддержки);
   `reportDescriptionlessDisables` и `reportNeedlessDisables` — исключение
   без причины или мёртвое не проходит; `value-no-unknown-custom-properties`
   с `importFrom` — мёртвая ссылка на роль не проходит;
   (б) `token-layer.test.ts` — «узел не читает `--space-\d`» и «роль не
   получает число» — храповиком: ноль у третьей витрины, база у пакета;
   (в) `css-tokens.test.ts` — читаемая переменная объявлена;
   (г) `nearStep` набора — на шкалу отступов;
   (д) живой: свип ширин (320, 360, 384, 393, 414, 600…1600 и складные
   690/829/836/842) без переполнения и скачков; ритм полос одним числом; поле
   ≥ 8 у листа; «воздух дважды» и «столкновение» — семьи `field` / `twoAir` /
   `collision` cbdin.

**Порядок коммитов:** запись в `DECISIONS.md` → подготовительный рефакторинг
(глоб линтера, корни тестов, `brandTheme` на третьей витрине) → основание
шкалы в комментарии → роли + псевдонимы с нулевым диффом → сторожа
красным-зелёным → слой витрины своими числами → админка → показ в
`/admin/design`.

### 3.5. Развилки, которые решает владелец

1. **Единица.** (а) px везде — одна единица на платформу, поля не растут со
   шрифтом браузера; (б) **rem у ролей третьей витрины при px-примитивах** —
   поля текста растут с кеглем, разница единиц у двух витрин записывается;
   (в) вся платформа на rem — большая отдельная работа. Профессионалы
   расходятся честно (СПОРНО). Рекомендация: **(б)**, с разделением по
   Comeau: rem — где отступ служит чтению, px — где не должен расти
   (цель, зазор, рамка, шов).
2. **Откуда числа**, пока макета нет: (а) механизм и роли сейчас, числа — по
   замеру люкс-магазинов и от кегля тела, владелец крутит из админки; макет
   потом уточняет; (б) только механизм, значения прежние; (в) ждать макет.
   Рекомендация: **(а)**.
3. **Множитель плотности** — нет, пока не попросит владелец.

## 4. Перепроверка палитры — чек-лист

По Material 3 (`material-color-utilities`, токены), Radix Colors (файлы
`light.ts` / `dark.ts`, генератор, пересчёт APCA), CSS Color 4, APCA
(Myndex), Refactoring UI, Baymard и NN/g. Пункт — как проверить машиной —
порог.

**Устройство (СИЛЬНО — обе системы):**

- **Ступень — работа, не число.** Radix: 12 ступеней, у каждой одна роль
  (1–2 фон, 3–5 поверхности интерактивных, 6–8 рамки, 9–10 заливки, 11–12
  текст). Проверка: 12 строк, ни одной ступени с двумя ролями.
- **Три яруса, ссылки в одну сторону.** hex/rgb/oklch — только в файле
  палитры; роли ссылаются на палитру/`brandTheme`; узлы — только на роли.
- **Тёмная — своя таблица, не инверсия.** Material: поверхности тон 4–24,
  акценты 80 вместо 40, их «on» — тон 20; Radix: `dark.ts`, ступень 9 та же,
  10 светлее. Проверка: тёмная бумага T 4–8, поднятая поверхность выше на
  4–6 тонов, хрома ≤ 0.02.
- **Серые подкрашены брендом, но едва**: Material chroma 6–8 из 120; Radix
  OKLCH C ≤ 0.02.
- **У каждой заливки есть пара**: «on» вычисляется, а не константа `white`.
- **Тон меряется по L* или Y по WCAG — не по HSL-lightness.**

**Пороги (СИЛЬНО — WCAG 2.2 / Material / Radix):**

- Текст на фоне ≥ 4.5 : 1 (Material для основного — 7 : 1); APCA: 11-я на
  2-й ≥ Lc 60, 12-я ≥ Lc 90; WCAG — ворота (EN 301 549), APCA — предупреждение
  для тёмной (формула WCAG в тёмных парах завышает контраст).
- Акцент против **худшей** поверхности (surface-dim ~T87 в светлой,
  surface-bright ~T24 в тёмной), не фона страницы.
- **Заливка не живёт в тонах 50–59**: ни белый, ни чёрный текст не даёт 4.5;
  коридор Radix для ступени 9: L* 45–62 (белые чернила) или 83–91 (тёмные).
- Рамка органа управления и кольцо фокуса ≥ 3 : 1; **ступени 6/7/8 Radix этого
  не берут** (1.4–2.4 в светлой), `--focus-8` не копировать — кольцо замером
  (у нас 11-я; верно).
- Разделитель декоративный, но не исчезает: |ΔL*| ≥ 6.
- Наведение/нажатие заливки: |ΔL*| 2.5–4.6 светлая (темнит), 3.6–6.6 тёмная
  (светлит); чернила читаемы на всех состояниях.
- Ошибка отличима от марки: ΔE76 ≥ 25; семантика (ошибка, скидка, успех) —
  те же четыре роли и тона (40 / 80, контейнер 90 / 30).
- Alpha-вуали считаны от **бумаги набора**, не от белого (≤ 4 уровня канала
  расхождения со сплошной ступенью).
- Тон шкалы не плывёт: OKLCH |Δh| ступеней 3–11 к seed ≤ 10°.
- Поле палитры в админке принимает hex/rgb/hsl; oklch и P3 не пройдут regex —
  расширить или написать в подсказке.

  Хорватия — 414, 384, … Ширины 375 нет в первой шестёрке. Свип: 320 (переток
  = зум 400 %, WCAG 1.4.10), 360, 384, 393, 414; альбом 780×360, 873×393,
  896×414; складные 690/829, 836/842 — по обе стороны шва.
- **Медиазапрос — для окна** (шапка, колонки, подвал); **контейнерный — для
  узла** (карточка, плитка, промо): `container-type: inline-size` на
  обёртке-ячейке; `size` без явной высоты — запрещён (схлопывается в 0).
  Внутри узла — `cqi`.
- **Рампа с px/rem-слагаемым**: голый `vw` не растёт при зуме — провал WCAG
  1.4.4 (F94).
- **Сетка `repeat(auto-fit, minmax(min(<плитка>, 100%), 1fr))`** — внутренний
  `min()` обязателен.
- **Flex-потомок с текстом — `min-width: 0`**; `nowrap` — только с
  комментарием. `overflow-wrap: anywhere` (учитывается в min-content),
  `hyphens: auto` + `lang` — как улучшение (§5.4).
- **Единицы окна**: шторки и окна — `max-height: 100dvh`; герои — `clamp()` по
  высоте, не `100svh`; на корне `scrollbar-gutter: stable`; `100vw` —
  запрещён.
- **Safe area**: `viewport-fit=cover` + `max(своё, env(safe-area-inset-bottom))`
  у нижней полосы; экранная клавиатура (Chrome 108+ / Safari: resizes-visual)
  — полоса от `visualViewport`.
- **Цель 44 × 44, зазор ≥ 8** (WCAG 2.5.8 — 24 юридический минимум); под
  `(pointer: coarse)`; `:hover` под `(hover: hover)`; по `pointer` / `hover` /
  `orientation` не прячут содержимое и не меняют раскладку.
- **Baseline как правило кода** (20.09.2026): widely — прямо; newly — под
  `@supports`; не Baseline — украшение. Widely: контейнерные запросы, `dvh`,
  `clamp`, `aspect-ratio`, `@layer`, `color-mix`, `:has()`, `:focus-visible`,
  `<dialog>`, `inert`, `touch-action`; newly: anchor positioning (01.2026),
  стилевые контейнерные запросы (05.2026), `scrollbar-gutter`, `light-dark()`,
  Popover API (01.2025); Chrome-only: `interpolate-size`, scroll-state,
  viewport segments; scroll-driven animations — Firefox за флагом.

### 5.2. Темы (СИЛЬНО)

- **Переключатель — `color-scheme` на `<html>` из cookie на сервере; скрипта
  до отрисовки нет.** Без cookie — `light dark`; `<meta name="color-scheme">`
  раньше стилей. Три состояния (система / светлая / тёмная) сходятся —
  проверка тремя прогонами.
- **Токен цвета — один раз, `light-dark(светлый, тёмный)`** (Chrome 123,
  Firefox 120, Safari 17.5), с запасным путём; два блока `[data-theme]` — токен
  объявлен дважды.
- **С темой меняется только цвет**: тень несёт `light-dark()` внутри; вуаль —
  `color-mix()`, не `filter`.
- **Тёмная полоса на светлой — `color-scheme: dark` на полосе**; один
  признак, внутри обычные `var(--content)`.
- **Пакет переопределяется порядком слоёв каскада** (`@layer ds.tokens,
  ds.base, ds.components, shop;`), не специфичностью; CSS владельца — в
  `<style>` в `<head>` под nonce, без `style=""`. Не проверено: как Turbopack
  переносит `@import … layer()` — проверить сборкой до того, как строить.
- **Forced colors**: выживают обводки и `outline` — у кнопки `border: 1px
  solid transparent`, фокус `outline`; **`prefers-contrast: more`** усиливает
  токены, не рисует вторую тему.
- **Смена темы не анимируется**; `theme-color` — из файла токенов.

### 5.3. Поведение узлов (СИЛЬНО — спецификации, APG, `web-features`)

- **INP ≤ 200 мс** (75-й процентиль); ответ на касание — `:active` синхронно,
  не после сервера. 300-мс задержка снимается `viewport width=device-width`;
  `touch-action: manipulation` — в общем `pressable` как страховка.
- **`:focus-visible`** решает «фокус с клавиатуры» сам; кольцо ≥ 3 : 1 в обеих
  темах; свой детектор ввода не нужен.
- **`<dialog>` + `showModal()`** даёт `::backdrop`, Escape, фокус-ловушку,
  `inert` остальной страницы, верхний слой. **Не даёт** закрытие по клику
  вне: `closedby="any"` — Chrome 134+, Firefox ~137+, **Safari нет** →
  писать руками, `closedby` — улучшение. Фокус на открытии — на смысловое
  поле (клавиатура телефона без второго тапа); на закрытии — вернуть.
- **Popover API** — для немодального (язык, сортировка, подсказка); **anchor
  positioning** — с `position-try-fallbacks` и проверкой в Safari/Firefox
  (баги открыты).
- **Scroll-driven** — только под `@supports`, содержимое видно и без него;
  **View Transitions** — cross-document в Firefox нет; `unstable_ViewTransition`
  Next — буквально нестабильно; **`prefers-reduced-motion`** — обязательная
  пара к каждому такому блоку.
- Не покрыто: APG combobox / listbox / tabs — понадобятся для выбора города и
  пункта выдачи.

### 5.4. Текст на четырёх языках (СИЛЬНО — W3C, MDN, ICU исполнён)

- **Расширение при переводе зависит от длины строки, не языка**: до 10
  знаков — 200–300 %; 11–20 — 180–200 %; 21–30 — 160–180 %; 31–50 —
  140–160 %; 70+ — 130 %. Кнопки и бейджи («Buy», «New», «-20 %») распухают
  втрое: ширина под них не число из макета, а `min-width` + перенос.
- **`hyphens: auto` работает только с `lang` и словарём в браузере.** У
  Chromium есть `hyph-hr`, `hyph-it`, **нет `hyph-ro`** — на cbdin.ro, первом
  рынке, перенос румынских слов в Chrome не сработает молча. Обязательный
  минимум — `overflow-wrap: anywhere` и `<wbr>` / `&shy;` (уже есть
  `breakable()`).
- **`text-wrap: balance`** — заголовки до 6 строк (Chrome 130+, Firefox 121+,
  Safari 17.5+); **`pretty`** — Firefox не поддерживает вовсе; только
  улучшение.
- **Кавычки по языку страницы**: hr и ro — „…“, it — «…», en — "…";
  `quotes: auto` работает там, где стоит `lang`.
- **Цена — два параметра, не одна локаль**: `Intl.NumberFormat(язык страницы,
  { currency: валюта магазина })`. Проверено: `it-IT` не ставит разделитель
  тысяч до 10 000 («1234,00 €» — правильно, не чинить); `en` + RON →
  «RON 39.90». **Дата** — только `Intl.DateTimeFormat`: hr-HR «20. 09. 2026.»
  (с точкой в конце), ro-RO «20.09.2026», it-IT «20/09/2026».
- **Румынские ș/ț (U+0219/U+021B) ≠ ş/ţ (седиль)**: подмена не видна глазом,
  ломает поиск и сортировку — сторож, как «кириллица в английских полях».
- **Сортировка — `Intl.Collator(locale)`**, иначе Č/Š/Ž встают не по алфавиту.
  `text-transform: capitalize` для хорватских диграфов — верен, свой хелпер не
  нужен.

### 5.5. Страницы магазина (СИЛЬНО — Baymard, замеры 2024–2026)

- Активный раздел в шапке и меню выделяется цветом токена (95 % сайтов не
  делают); заголовок категории в мегаменю — сам ссылка (33 % — нет); задержка
  300–500 мс перед hover-меню на широкой.
- Поиск: видимая кнопка рядом с полем ≥ 44 (27 % мобильных — нет); понимает
  «symptom» и «use case» запросы («не могу заснуть» → `/sleep`) — 37 / 43 %
  сайтов проваливают; подсказки и опечатки — по каждому языку отдельно; «ничего
  не найдено» ведёт на эффекты и каталог (50 % — тупик).
- Фильтры: аналог пяти базовых для CBD — цена, эффект, концентрация, объём,
  форма; **чекбоксы, не radio** (14 % ломают); на телефоне — шторка `<dialog>`
  с липким триггером и кнопкой «Показать N товаров»; на широкой — мгновенно
  без «Применить»; состояние — в адресе (переживает «Назад»); сортировка —
  цена, рейтинг, хиты, новинки (68 % не дают все четыре).
- Карточка в списке: **≥ 3 фото** (80 % — меньше): бутылка, этикетка крупно,
  в контексте; **цена за единицу** — для CBD за мг, не только за мл (67–87 % не
  показывают).
- Страница товара: варианты — кнопками с «нет в наличии», не `<select>` (57 %);
  **оценка доставки рядом с ценой** (67 % — нет; 40 % отказов — «слишком
  высокие доп. расходы»); **ссылка на возврат в основном контенте** (44 % —
  нет; для вскрываемого товара — доверие не меньше сертификата); галерея —
  pinch и double-tap zoom одновременно (этикетка, партия, QR); липкая кнопка
  покупки с полями по бокам, не во всю ширину, место занято заранее.
- Корзина: количество — кнопки +/− (97 % — голое поле); после «в корзину» —
  шторка с содержимым и «продолжить покупки»; на телефоне автопрокрутки
  каруселей нет.
- Главная показывает ≥ 40 % типов товаров, не одну промо-линейку.
- Vercel WIG: `tabular-nums` у цен и счётчиков; обязательные **и**
  необязательные поля помечены оба; гостевое оформление заметнее входа;
  ошибка называет именно то, что не так; значок доверия у поля карты, не в
  подвале.

### 5.6. Закон ЕС в интерфейсе (СИЛЬНО для норм ЕС — eur-lex прочитан; УМЕРЕННО для деталей RO/HR — вторичные источники, ANPC и legislatie.just.ro не открылись)

Что обязано быть на экране — это компоненты, и закладываются они до слоя
«страницы»:

- **Бейдж скидки не существует без второй строки** «самая низкая цена за 30
  дней: X» (Omnibus 2019/2161, ст. 6a в 98/6/EC; для товаров младше 30 дней —
  весь срок продажи). В Хорватии действует с 28.05.2022. Движку нужна
  история цены за 30 дней по каждой валюте.
- **Цена за единицу** рядом с ценой везде, где показана цена (98/6/EC ст.
  3(4)): для масел — за 10 или 100 мл; на 375 — отдельная строка под ценой.
- **Цена с НДС и известными сборами до оформления** (CRD 2011/83 ст. 6(1)(e));
  ставка — параметр страны, не константа: **RO 21 %** (с 08.2025), **HR 25 %**;
  двойные цены HRK/EUR в Хорватии не нужны с 01.01.2024.
- **Кнопка заказа — «заказ с обязательством оплаты»** или равнозначно
  недвусмысленно (CRD ст. 8(2)), иначе покупатель не связан; свой текст на
  каждом из четырёх языков, «Купить» не годится.
- **14 дней отказа не действуют для вскрытых запечатанных товаров**
  (гигиена/здоровье, CRD ст. 16(e)) — флаг на карточке масла/капсул и в
  тексте возврата.
- **Данные производителя / ответственного лица в ЕС — на самой карточке
  товара**, не только в подвале (GPSR, с 13.12.2024).
- **Cookie**: «принять всё» и «отклонить всё» — одного веса и в один клик,
  без предустановленных галочек (EDPB 05/2020, 03/2022 — по вторичным
  источникам); шторка — тот же `<dialog>` + `showModal()`.
- **Платформа ODR закрыта**: регламент 524/2013 отменён с 20.07.2025
  (2024/3228) — ссылка `ec.europa.eu/consumers/odr` мертва, в подвал не
  класть; сторож на строку.
- **Румыния**: пиктограмма SAL 250 × 50 на первой странице и в меню со
  ссылкой на `reclamatiisal.anpc.ro`; SOL с 05.2026 не требуется (приказ
  ANPC 270/2026 — УМЕРЕННО).
- **Хорватия**: с 19.06.2026 — онлайн-кнопка одностороннего расторжения
  договора в кабинете/заказе, не в условиях мелким шрифтом (УМЕРЕННО).
- **Возраст 18+ для CBD** — статьи закона нет ни в RO, ни в HR: ворота
  возраста — решение владельца о риске, а не «по закону №…».
- **Novel Food**: проглатываемый CBD (масла, капсулы) — Novel Food без
  завершённого одобрения на 2026; топики — косметика. Каталогу нужен признак
  «проглатываемое / наружное», он меняет текст о законности на карточке.
