# Образцовая витрина CBD на Next.js — шаблон румынского рынка

Замысел согласован с заказчиком 23.09.2026 (вариант А). Документ — для
исполнителей: что строится, из чего, чем меряется готовность.

## Цель

Скил строит витрины CBD-магазинов на Next.js над Vendure (торговля) и Payload
(контент) и проверяет готовые сайты. Ему не хватало **образца**: витрины,
собранной целиком из основы скила, на которой видно «как должно быть» и по
которой сверяются чужие сайты. Образец — шаблон для **румынского рынка**,
ставится установщиком скила в новую папку и работает сразу — на образце
данных, а на настоящих Vendure и Payload — переключением двух настроек.

## Что входит

- Вся покупка гостем: главная, категория с фильтрами и страницами, поиск,
  товар с вариантами, корзина, оформление заказа по шагам до «спасибо».
- Личный кабинет: регистрация, вход, выход (с закрытием сессии на сервере),
  «забыли пароль» (запрос и новый пароль), мои заказы и заказ подробно,
  адреса (добавить, изменить, удалить), профиль.
- Обязательные страницы: о нас, доставка и оплата, контакты, условия,
  конфиденциальность, возврат; «не найдено», ошибка, «магазин временно не
  отвечает».
- Служебное: карта сайта, robots, canonical, hreflang, JSON-LD
  (Organization, WebSite, BreadcrumbList, Product с Offer, FAQPage).

## Чего не входит

Онлайн-оплата картой (только интерфейс способа оплаты и наложенный платёж;
провайдер — позже, на сервере Vendure). Сравнение товаров, избранное,
отзывы с отправкой (показ отзывов из данных — да). Админка: её роль — у
Payload и Vendure. Многомагазинность (несколько витрин на одном движке).

## Рынок: Румыния

| Что | Как |
| --- | --- |
| Языки | ro (основной, в корне адреса `/ro`), en, hu; язык — сегмент адреса; `hreflang` на три языка и `x-default` → ro |
| Валюта | RON (lei); формат через `Intl` с локалью языка; точность — `MoneyStrategy` сервера (2) |
| Доставка | курьер до двери; постамат (easybox и подобные) — выбор точки из списка данных; стоимость и сроки — из данных |
| Оплата | ramburs (наложенный платёж) — обработчик на сервере Vendure; в образце — тот же путь через машину состояний |
| Обязательное в подвале | реквизиты компании (CUI, Nr. Reg. Com.) из данных; ссылки ANPC (SAL) и платформа споров ЕС (SOL) — знаки и адреса из данных, тексты утверждает заказчик |
| Буквы | румынские `ș ț` (U+0219/021B), не седильные — меряет словарь (`auditWords`); венгерские `ő ű` — шрифт обязан их иметь (стенд шрифта) |
| Слова | `docs/words.md` витрины с колонками ro · en · hu; формулировки утверждает заказчик |

Правовой статус товара и обещания о здоровье — не вёрстка: на витрине их нет,
тексты — от заказчика.

## Устройство

```
templates/storefront/          исходник шаблона в наборе
  app/[lang]/…                 страницы: собирают данные и отдают их блокам
  app/api/revalidate/route.ts  подписанный сброс кэша (HMAC, окно 5 минут)
  app/api/preview/route.ts     предпросмотр черновика Payload (подписанный токен)
  components/…                 блоки: получают нейтральные данные пропсами
  lib/source/contract.ts       договор данных: Product, Variant, Collection,
                               Facet, Cart, Order, Customer, Address, Page,
                               Block, LabReport, Market
  lib/source/index.ts          выбор источника по настройке SOURCE=sample|live
  lib/source/sample/…          образец CBD-магазина (данные + in-memory корзина,
                               заказы, покупатели — сбрасываются при перезапуске)
  lib/source/vendure/…         адаптер Shop API на assets/vendure (request,
                               result, money, search, asset, product)
  lib/source/payload/…         адаптер контента Payload (REST, язык, черновики)
  lib/cache-tags.ts            один реестр тегов: vd:*, cms:* — по ID, не по slug
  lib/href.ts                  одна функция адреса для всех ссылок, карты,
                               canonical и сброса кэша
  lib/i18n/{ro,en,hu}.ts       слова интерфейса (из docs/words.md)
  styles/                      основа скила: палитра, шкалы, роли, примитивы,
                               кнопка, каталог кнопок, поле, «куда ведёт», знаки
  docs/words.md, decisions.md  слова и решения витрины
  tests/…                      юнит-тесты договора и адаптеров; e2e Playwright
```

Правила, по которым написан каждый файл: `CLAUDE.md` набора (десять запретов,
переносимость), скиллы craft, palette, scale, code, shop, справочники
`vendure.md` и `payload.md`. Компонент не ходит в бекенд и не считает деньги
(`check:port`: `backendInView`, `moneyMath`). Tailwind и UI-киты не
используются: вид — основа скила.

**Стек:** Next.js 16 (App Router, `cacheComponents`), React 19.2,
TypeScript 6, CSS-модули, `graphql` (печать и проверка документов против
снимка схемы), Playwright (e2e), oxlint (через набор). Версии закрепляются
в lock-файле.

## Данные

**Договор** — нейтральные типы; компонент знает `Product`, а не Vendure.
Деньги — целые в минорных единицах + код валюты; «цена от» отличается от
цены варианта; ноль — цена, отсутствие — не цена. Отказ источника —
отдельное состояние (`unavailable`), не пустой список.

**Образец** — 12–16 CBD-товаров (масла разной силы и объёма, капсулы,
косметика, для животных) с вариантами, категориями, гранями (форма, сила),
партиями и протоколами лаборатории, страницами и блоками главной на трёх
языках. Снимки — нарисованные заглушки с пометкой «образец»; флаги
настоящести (`*_IS_REAL = false`) закрывают разметку цены и карту сайта от
поиска, пока данные не настоящие.

**Vendure** — по `references/vendure.md`: канал явный (`vendure-token`),
язык и валюта параметрами, сессия — cookie `httpOnly; secure;
sameSite=lax`, `logout` с токеном; каждая мутация читает `ErrorResult`;
оформление — машина состояний заказа; фильтр — ИЛИ внутри грани; номер
страницы — 404 на мусоре; картинки — сервер ассетов с `srcset`. Снимок схемы
Shop API (интроспекция публичного демо Vendure 3.x) лежит в шаблоне; тест
проверяет каждый документ адаптера против него.

**Payload** — по `references/payload.md`: реестр блоков с проверкой в обе
стороны, одна функция адреса, язык без отката для юридических страниц,
предпросмотр по подписанному токену без кэша, сброс кэша подписанным
запросом с тегами старой и новой версии.

## Кэш

Публичное (каталог, товар, страницы) — `'use cache'` с языком, валютой и
каналом аргументами и тегами из `lib/cache-tags.ts`; личное (корзина,
счётчик в шапке, кабинет) — динамическое, без общего кэша. Внутри публичного
кэша нет `cookies()`, `headers()` и токена (тест). Сброс — `/api/revalidate`.

## Вид

Основа скила без исключений: шкалы, двенадцать примитивов, три шва, кнопка
основы со стилем из каталога, поле, «куда ведёт», лист знаков, обе темы.
Меню и выпадающие списки — верхний слой браузера (`popover`), без Radix и
числовых слоёв (правило 8). Стиль кнопок и шрифт витрины выбирает заказчик
(стенды); до выбора — «Пилюля» и системный шрифт.

## Готовность — чем меряется

1. Проверки набора на шаблоне зелёные: `check:css`, `check:code`,
   `check:lint`, `check:port`, `typecheck`, `test`, `check:seo`,
   `check:urls`, `check:open`, `check:icons`, `check:buttons`,
   `check:scale`, `check:palette`, `check:stage`.
2. Свип всех форм страниц на 41 ширине мышью и пальцем, в обеих темах — без
   прокрутки вбок, вылетов, обрезки, наездов, мелких целей и ступенек;
   `check:craft` — контраст и цели по отрисованному.
3. e2e Playwright на образце:
   - гость: категория → фильтр → товар → вариант по адресу → корзина →
     изменить количество → код скидки (ошибка и успех) → оформление
     (контакты, адрес, доставка, ramburs) → «спасибо» с номером заказа;
     Back между шагами не стирает введённое;
   - покупатель: регистрация → выход → вход → заказ из корзины → заказ в
     «Моих заказах» → адрес добавлен, изменён, удалён → выход, и старый токен
     больше не работает;
   - края: пустая корзина, фильтр без результатов, `?page=abc` → 404,
     неизвестный товар → 404, источник недоступен → честный экран,
     «нет столько на складе» → частичный успех с сообщением.
4. Адаптеры Vendure и Payload — тесты на заготовленных ответах сервера
   (ErrorResult, InsufficientStockError, отказ оплаты, неверный пароль,
   чужой язык, неизвестный блок) и проверка документов против снимка схемы.
5. Lighthouse CI на собранном шаблоне: доступность 100, производительность в
   бюджете `assets/quality/lighthouserc.cjs`.
6. Установка: `node install.mjs --storefront D:\BusinessProject\cbd-storefront-demo`
   → `npm install` → `npm run build` → запуск; снимки главной, категории,
   товара, корзины, оформления и кабинета на телефоне и компьютере — заказчику.

## Поставка

- `templates/storefront/` в наборе; режим установщика `--storefront <папка>`
  копирует шаблон и основу, пишет `package.json`, `kit.config.json`,
  `.env.example` (`SOURCE`, `VENDURE_SHOP_API_URL`, `VENDURE_CHANNEL_TOKEN`,
  `PAYLOAD_URL`, `REVALIDATE_SECRET`, `PREVIEW_SECRET`), CI из
  `templates/check.yml`.
- Задача CI набора `storefront`: установка шаблона во временную папку,
  сборка, проверки, e2e, Lighthouse (стандартный раннер, отчёты 7 дней).
- Скилл `site-building`: справочник «Образцовая витрина» — порядок работы с
  шаблоном и сверка чужого сайта с ним (основа будущего аудита).
