## Что оставлено и почему

`research/` содержит 869 файлов, примерно 25.6 MB. У него есть реальные потребители:
`tools/palette-profile.mjs`, `tools/pro-check.mjs`, `pro/основание.json`.
Удаление всего архива сейчас оборвёт проверяемое происхождение и часть генерации.
Архив не устанавливается в production-сайт; массовое удаление не выполнено.
Сторонние навыки оставлены для явного `--extras`, но не идут по умолчанию.
Существующий CSS-профиль не объявлен единственно правильным для каждого нового сайта.

## Проверки этого изменения

- `npm test`: 52 теста инструментов и 35 selftests; последние дополнены пятью commerce-сценариями
  и исполнением экспортированных commerce/quality ресурсов вне репозитория.
- `check:rules`: 238 правил согласованы; `check:scale`, `check:palette`,
  `pro:check`, `check:skill` проходят. Для ресурсов проверены 23 записи,
  лицензии, пути, локальные ссылки и сохранённые хеши, включая CRLF.
- `check:code` и `check:port` проходят, но набор не содержит production-блоков:
  это НЕ доказательство переносимости готовой витрины на PHP/Twig.
- `check:css` проходит с существующим baseline: twiceDrawn=2, deadDress=1,
  plateGap=1, tramp=1. Эти сообщения не удалялись и пороги не ослаблялись.
- `python -X utf8 .../skill-creator/scripts/quick_validate.py skills/site-building`:
  валидный skill. Явный UTF-8 нужен для русских файлов на Windows.
- `selftest/component-preview`: настоящий код выбранных компонентов, Vite build,
  строгая TypeScript-проверка и Playwright на 375/1280 px в светлой/тёмной теме.
  Действия, клавиатура, возврат фокуса, немодальность, checkbox, раскрытие
  навигации, загрузка SVG, отсутствие переполнения и JS-ошибок.
  Снимки и JSON — `dist/component-review`, в CI публикуются artifact.
  Снимки просмотрены; промежуточное состояние CSS-перехода исключено из захвата.
- Lighthouse CI действительно запущен локально. Первый запуск нашёл favicon 404
  (исправлено) и превышения LCP/script transfer. Диагностика показала, что браузерный
  транспорт окружения отдаёт распакованный ответ: вместо `Content-Encoding: br`
  браузер видит `x-content-encoding-over-network: br`. Прямой Node-запрос к тому же
  серверу получает gzip/br. Следовательно, локальный transfer/LCP здесь измерен
  с изменённой сетевой цепочкой; пороги не ослаблялись. Результат обычного GitHub
  runner фиксируется отдельно, локальная ошибка не объявлена зелёной.

Ограничения: нет полного WCAG-аудита, screen reader и всех браузеров; нет установки
в production WordPress/OpenCart, реального checkout или нового PDF сайта.
Vite предупреждает о `use client` у библиотек: этот стенд — клиентский SPA,
а серверные React-границы проверяются в выбранном framework-проекте.
Зелёные проверки набора не подменяют финальную приёмку конкретного сайта.

## Как выбирать дизайн

Рекомендация — гибрид. В диалоге определяем задачу, контент, структуру и несколько
направлений. На живой странице совместно сравниваем палитру, типографику, ритм
и компоненты. Утверждаем цельный вариант, а не набор изолированных настроек.
После утверждения фиксируем snapshot и передаём MD/PDF/токены/очищенную копию
для следующего этапа. Конструктор остаётся мастерской; production — отдельный
выбранный проект. Для разового небольшого сайта необязательна полная панель;
для повторяемой работы владельца она полезна как ускоритель выбора.
