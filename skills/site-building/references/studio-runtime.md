# Исполняемое ядро мастерской

Эти механизмы уже существуют в [assets/studio](../assets/studio), а не только
описаны как будущие требования. Применять при новой мастерской и переносе
существующей. Для обычного сайта без редактора не включать runtime в production.

## Установка и обновление

Из установленного скилла:

```sh
node scripts/install-studio.mjs /absolute/site/packages/studio-core
node scripts/install-studio.mjs /absolute/site/packages/studio-core --check
```

Путь задаётся явно. Установщик записывает SHA-256 в `studio-source.json`, сначала
проверяет весь набор и отказывается перезаписывать местные изменения.
Не применять `--force` или ручную замену, пока не разобрана разница.
Неуправляемые файлы сохраняются. Устаревшие файлы не удаляются автоматически.
Общий установщик набора также хранит `.site-kit-install.json`: старый сайт без
этой записи требует сравнения инструментов перед обновлением.

В репозитории набора движки генерируются из `tools/scale.mjs`, `tools/palette.mjs`
и их конфигурации: `npm run studio:sync`, затем `npm run studio:check`.
Это генерация платформенного ввода-вывода, не вторая реализация математики.
Обновлять `upstream.json` вместе с осмысленным изменением собственных ресурсов;
не пересчитывать чужие контрольные суммы ради обхода проверки.

## Граница ядра и профиля

| Модуль | Общий механизм | Что остаётся в сайте |
| --- | --- | --- |
| `snapshot.mjs` | Канонический JSON, оболочка версионного parser, fingerprint, проверка утверждения | Схема, допустимые поля и реальные миграции старых версий |
| `store.mjs` | Черновик, применение, утверждение, localStorage, межвкладочная синхронизация, ошибки записи | Ключ хранилища, defaults, parser, проверки, вычисление токенов, React-обёртка при необходимости |
| `engine/` | Единые расчёты шкал и цвета | Настройки бренда, выбранные роли, разрешённые диапазоны и данные |
| `document.mjs` | Безопасный Markdown → HTML → PDF через переданный Playwright | Полное содержательное описание конкретного сайта |
| `handoff.mjs` | Один снимок и текст для MD/PDF, manifest, хеши файлов, защита путей | Сбор исходников, архиватор и серверный обработчик |
| `selection.mjs` | Замыкание явного графа компонентов, CSS и ресурсов | Реестр зависимостей и реальный потребитель выбранного списка файлов |

Подключать `createStudioStore` с `projectId` и `resolveTokens`, чтобы изменение
движка после обновления снимало актуальное утверждение даже при прежних настройках.
`extras/readExtras` позволяют сохранить местные библиотеки пресетов и их формат.
Не переименовывать существующий ключ localStorage без миграции. Неверный пресет
не перезаписывать; quota/privacy-ошибку показывать, не сообщая о сохранении.

Данные CMS/commerce приходят через backend-neutral provider. Payload/Vendure —
основной профиль; ядро не импортирует их SDK. Для WordPress/OpenCart возможен
тот же браузерный JS и отдельно серверный/сборочный адаптер. Нативные PHP/Twig
темы этим тестом не реализованы и не сертифицированы.

## Утверждение и передача

1. Снять копию текущего дизайна, проверить её, рассчитать токены общим движком.
2. Только по действию владельца создавать `actor: owner-ui`. Автотесты используют
   `verification`; обычный экспорт без подтверждения получает `draft`.
3. Зафиксировать projectId, sourceRevision, время, дизайн и токены. SHA-256 —
   идентификатор согласованного содержимого, **не цифровая подпись личности**.
4. Собрать выбранные компоненты с транзитивными стилями/ресурсами в отдельную
   копию. Список графа должен управлять копированием, не быть декоративным отчётом.
5. Передать полный Markdown в `createHandoff`; PDF рендерится из этого же текста.
   Сохраняются `design-snapshot.json`, `approval.json` при подтверждении,
   `export-manifest.json`, MD/PDF. Проверить сохранённый статус и fingerprint.
6. Перед применением ответа повторно сравнить снимок с текущим черновиком.
   Изменение во время сборки не должно утверждать другой вариант. Ошибка
   сохранения не должна менять применённый/утверждённый снимок.
7. Перезагрузить страницу, изменить настройку и подтвердить снятие статуса.
   Историческое утверждение сохраняется отдельно, не выдаётся за актуальное.
8. Установить зависимости и собрать экспорт отдельно, открыть его в браузере,
   сравнить размеры/токены и проверить отсутствие редактора, альтернатив и секретов.
   Просмотреть страницы PDF, а не только заголовок `%PDF-`.

## Проверка переноса

В полном репозитории `selftest/studio-pilot` — независимая мастерская «Север»
на обычном JS, с другим брендом, контентом и версией схемы. Она устанавливает
это же ядро, мигрирует v1 → v2, проверяет preview/сохранение, формирует проверочный
пакет, собирает его и сравнивает с живой страницей при 375/768/1280 px.
Сценарий также проверяет увеличение текста, недоступный provider, клавиатуру,
немодальное сворачивание и снятие утверждения после правки.

```sh
node selftest/prepare-studio-pilot.mjs /absolute/empty/pilot
cd /absolute/empty/pilot
npm ci
npx playwright install chromium
npm start
# В другом терминале этого проекта:
npm run verify
```

Этот опыт подтверждает перенос **механизмов**. Он не заменяет проверку полного
ассортимента, реальной оплаты, SEO, доступности и производительности нового сайта.
Детальный маршрут передачи: [handoff.md](handoff.md).
