# Payload за витриной Next.js

Применять, когда тексты, страницы, навигация, SEO и медиа витрины живут в
Payload 3.x, а торговля — в Vendure ([vendure.md](vendure.md)). Сверено с
шаблоном `templates/website` и плагинами Payload v3.90.1 (MIT); ошибки
шаблона ниже названы, чтобы их не переносить. Коммерческий шаблон и
`plugin-ecommerce` при Vendure не используются: второй источник цены, остатка
и заказа.

## Порядок работы

1. **Разделить владельцев полей** (таблица «Договор» ниже) и записать в
   `docs/decisions.md` витрины до первой коллекции.
2. **Реестр блоков** — схема блока и его отрисовка в одном реестре.
3. **Одна функция адреса** — `hrefFor()`; из неё карта сайта, ссылки,
   переадресации, `canonical`, `og:url` и сброс кэша.
4. **Сброс кэша и предпросмотр** — по матрице ниже, подписанным запросом.
5. **SEO, переадресации, медиа, языки** — по разделам.
6. **CBD-коллекции** — протоколы лаборатории, юридические страницы рынка,
   проверка формулировок при публикации.
7. **Проверка** — сценарии в конце.

## Договор Payload ⇄ Vendure ⇄ витрина

| Кто владеет | Что |
| --- | --- |
| Vendure | товар, вариант, SKU, slug товара по языкам, опции, цена, налог, остаток, доступность в канале, заказ |
| Payload | страницы и блоки, навигация, частые вопросы, SEO-переопределения, юридические тексты, протоколы лаборатории, медиа редакции |
| Витрина | собирает оба ответа; цену не считает, факт не дублирует |

* Связь товара: поле Payload `contentKey` = пользовательское поле Vendure
  `contentKey`; вариант — по SKU. Числовые ID баз не годятся: они разные на
  разработке, в тестовой и в бою. Сироты с обеих сторон — отчётом, не молча.
* Цена, наличие и название варианта в Payload не копируются.

## Реестр блоков

Шаблон сопоставляет тип блока с компонентом (`RenderBlocks.tsx`) — это
берётся. Не берётся: `key={index}`, `@ts-expect-error` и молчаливый
`return null` для неизвестного блока. Карта типизируется
`satisfies Record<BlockType, Renderer>`; неизвестный блок в разработке — видимая
ошибка, в бою — пропуск с записью в журнал. Проверка в обе стороны: блок CMS
без отрисовки и отрисовка без блока — как швы в `check:css` (`deadSeam`).

## Одна функция адреса

В шаблоне адрес собирается в восьми местах и расходится: главная — то `/`,
то `/home`; префикс `/posts` теряется в `generateURL`. Витрина держит одну
`hrefFor({ collection, slug, locale })` рядом с деревом маршрутов
(`tools/routes.mjs`); склейка адреса из slug в другом месте — дефект.

## Сброс кэша

| Событие | Сбросить |
| --- | --- |
| публикация, правка опубликованного | теги документа по всем языкам |
| смена slug опубликованного | старый и новый адрес + постоянная переадресация старого |
| снятие с публикации, удаление | теги документа, списки и карта сайта |
| глобальный документ (шапка, подвал) | `cms:global:{slug}:{lang}` — все страницы |
| публикация одного языка, по расписанию | только этот язык; расписание — тем же хуком |

* Теги — по ID, не по slug: `cms:page:{id}`, `cms:global:header:{lang}`,
  `cms:sitemap:{lang}`, `cms:redirects`, `cms:lab:{batch}`. Один модуль тегов
  на витрину и админку; строка тега в другом месте — дефект.
* `revalidateTag` в хуке админки чистит кэш только приложения админки.
  Витрина — отдельное приложение: хук `afterChange`/`afterDelete` собирает
  теги старой и новой версии и шлёт каждой витрине подписанный POST на
  `/api/revalidate` (HMAC по телу и времени, `timingSafeEqual`, окно 5 минут).
  Массовая заливка — `context.disableRevalidate`.
* Юридические и медицинские страницы истекают сразу; «отдать старое ещё
  раз» (`revalidateTag(tag, 'max')` шаблона) для них не годится.

## Черновики и предпросмотр

Вход: `livePreview.url` админки → `/api/preview` витрины с подписанным
токеном со сроком (не постоянный секрет в адресе) → проверка пути как
относительного своего → `draftMode().enable()` → чтение с `draft=true` без
кэша и тегов → выход отдельным адресом. Живое обновление при сохранении
принимает сообщения только от точного origin админки. Флаг `draft` сам
черновики не прячет — доступ коллекции (`authenticatedOrPublished`) обязателен.
Цены и наличие в предпросмотре — живые из Vendure; на странице — плашка
«предпросмотр».

## SEO и переадресации

* Поля — вкладка `plugin-seo` с подсказками длины (title 50–60, description
  100–150 знаков). `generateMeta` шаблона не берётся (`og:url` всегда `/`,
  нет `canonical` и языковых альтернатив): одна `toMetadata()` поверх
  `hrefFor()`, вывод меряет `check:seo`.
* Переадресации — `plugin-redirects` с включёнными `redirectTypes`, коды
  301/308, отдаются рано (middleware или `next.config`) из кэша с тегом
  `cms:redirects`; смена опубликованного slug сама создаёт 301. Шаблонная
  `redirect()` после «не найдено» даёт временный 307 — не годится.
* Цепочек и петель нет; цель открывается — `check:urls`.

## Медиа

`alt` обязателен и переводится по языкам (в шаблоне обязательность
закомментирована). Точка фокуса (`focalX/focalY`) — в `object-position`
кадра `frame`; размеры — именованные, `og` 1200×630. Не `quality={100}`,
`sizes` — по раскладке, не по ширинам файлов. Снимки шаблона не копируются:
отдельного разрешения на них нет.

## Языки и адреса

* Откат языка (`fallback`) по умолчанию включён: непереведённая болгарская
  страница молча печатает английский. Для юридических и медицинских текстов —
  `fallback: false` и «перевода нет» вместо чужого языка.
* Встроенный `slugify` удаляет всё не-ASCII: кириллический заголовок теряет
  буквы. Slug — локализованный, с транслитерацией языка; после публикации не
  перегенерируется (адрес — ключ, скилл `shop`).
* Статус публикации по языкам (`localizeStatus`) экспериментальный — не
  строить на нём выпуск.

## CBD

* **Протоколы лаборатории** — коллекция `labReports`: уникальный номер
  партии, SKU, лаборатория, дата, измеренные вещества, PDF. Текущая партия
  SKU — в Vendure; витрина показывает протокол только при совпадении партии.
* **Юридические страницы — по рынку, не по языку.** Язык ≠ рынок: поле
  `market` с составным уникальным ключом или плагин multi-tenant.
* **Формулировки о здоровье** проверяются при публикации полем `validate`
  (черновики по умолчанию не проверяются) тем же списком запретных фраз, что
  и проверка витрины; список и причины — скилл `shop`.
* **Возраст** — текст в глобальном документе рынка; сам запрос возраста —
  на витрине и при оформлении.
* **Формы** — через сервер витрины: ограничение частоты, скрытое поле от
  ботов, согласие, срок хранения. Открытое создание записей формы из браузера
  (`create: () => true` шаблона) не берётся.

## Сценарии проверки

Публикация, правка, смена slug (старый адрес — 301), снятие, удаление,
публикация одного языка, по расписанию; предпросмотр черновика не виден
гостю; неизвестный блок; кириллический заголовок; страница без перевода;
протокол другой партии не показывается; запретная фраза не публикуется;
недоступная админка — витрина отдаёт последнюю опубликованную версию или
честную ошибку, не пустую страницу.

## Как проверить готовую витрину

| Искать | Что значит |
| --- | --- |
| адрес склеен из `slug` вне одной функции | ссылки, карта сайта и canonical расходятся |
| `revalidateTag` только внутри админки | отдельная витрина не узнаёт о правке |
| тег кэша по slug | переименование оставляет старый кэш |
| `key={index}`, `return null` в отрисовке блоков | блоки путаются, новый блок исчезает молча |
| `redirect()` для переадресаций | временный 307 вместо постоянного |
| `alt` не обязателен, `fallback` включён для юр. текстов | пустые подписи, чужой язык на юридической странице |
| секрет предпросмотра строкой в адресе | черновики открываются любому, кто видел ссылку |
| `plugin-ecommerce` рядом с Vendure | две правды о цене и остатке |
