# Набор вёрстки

Скилл, шкалы, **палитра из двенадцати ступеней**, примитивы раскладки и
тринадцать команд проверки — то, что переживает конец проекта и не должно
собираться заново на следующем.

Что здесь решено раз и навсегда, чтобы не выводить заново:

- **Палитра** — не набор красок, а шкала из двенадцати ступеней на каждый
  смысловой цвет. Заказчик называет три краски на тему — фон, текст,
  фирменный, — остальные считаются, выпускаются в CSS одной командой и
  меряются; сколько именно и каких — таблица фактов, собранная из кода,
  в разделе «Палитра». Наведение и нажатие — соседние ступени, а не
  проценты от цвета кнопки. → скилл [`palette`](.claude/skills/palette/SKILL.md)
- **Размер, ритм, мера строки** — три шкалы, числа из них, а не из головы.
  → `craft/references/scales.md`
- **Раскладка** — одиннадцать примитивов, три брейкпоинта и ни одним больше.
  → `craft/references/layout.md`
- **Переносимость** — вёрстка обязана вставать на разный движок и бекенд, и
  это меряется, а не обещается. → `check:port`

Что за чем делается — следующим разделом; что лежит в наборе — таблицей «Что внутри».

## Как делается сайт: что за чем

Набор — это порядок, а не склад. Семь этапов идут воротами: следующий не
начинается, пока не держится предыдущий. Где вы сейчас, печатает
`npm run stage`; строка этапа стоит в `CLAUDE.md` проекта и переводится
только после разговора с заказчиком.

**Шаг 0 · Поставить набор.** `node install.mjs --palette "Имя" .` (раздел
«Поставить в проект» ниже) → `npm run stage` → прочитать `docs/start.md`:
фундамент раньше правил, храповики раньше долга.

| # | Этап | Что делается, по порядку | Скиллы | Ворота |
|---|---|---|---|---|
| 0 | Основание | 1) цвет — три краски → `npm run palette` → `check:palette` → роли в `tokens.css` → стенд и лист → слово заказчика в `docs/gate.md`; 2) размер и ритм — `styles/scale.json` → `npm run scale` → `check:scale` → стенд; 3) одиннадцать примитивов раскладки; 4) три брейкпоинта в `kit.config.json`; 5) проверки-храповики с первого коммита, CI из `templates/check.yml` | `palette`, `craft`, `code`, `stages` | шкалы и примитивы файлом; базы `check:css`, `check:code`, `check:port`; палитра и шкалы показаны заказчику |
| 1 | Каркас | адреса и дерево маршрутов (`tools/routes.mjs`) → язык адресом → данные одной таблицей в `lib/` → карта сайта и robots как механизм | `code`, `craft`, `shop`, `stages` | `check:open`, `check:urls` зелёные |
| 2 | Вёрстка | блоки и страницы из примитивов → обе темы → свип по ширинам → показать снимками | `craft`, `shop`, `code`, вкус и движение, `stages` | `check:craft` с базой, `sweep`; свип показан заказчику |
| 3 | Поведение | корзина, фильтры, формы, состояния (пусто, ошибка, ожидание); правка начинается с падающего теста | `code`, `shop`, `craft`, `stages` | `test`, `check:code`; действия отвечают |
| 4 | Наполнение | настоящие тексты, снимки с подписями, реквизиты, отзывы — от заказчика; флаги настоящести в `true` | `shop`, `craft`, `stages` | заглушек на витрине ноль |
| 5 | Сдача | карта сайта и разметка открыты поиску → вес, скорость, доступность → перенос на другие движки → внешний аудит | `shop`, `craft`, `palette`, `code`, `stages` | `check:seo`, доступность и переносимость на нуле; PageSpeed глазом |
| 6 | Жизнь | Search Console → замер после каждого выката → слежение, что адреса и разметка не уехали → новые тексты по спросу | `shop`, `craft`, `code`, `stages` | CI держит адреса и разметку |

Внутри каждого этапа тот же порядок: прочитать закон скилла → найти, где
факт живёт → сделать правку → прогнать проверки → показать отрисованным →
записать правило, если родилось. У каждого скилла этот порядок — свой раздел
(`check:rules` следит, чтобы он был). Полный реестр с воротами —
`tools/stages.mjs`, `npm run stage -- --all`.

## Поставить в проект

Из папки проекта, одной строкой:

```
git clone --depth 1 https://github.com/IgorAIdev/MySkilforCBDSiteBuilding.git /tmp/kit && node /tmp/kit/install.mjs . && rm -rf /tmp/kit
```

Агенту достаточно сказать словами: «установи набор из
https://github.com/IgorAIdev/MySkilforCBDSiteBuilding» — он склонирует и
разложит сам. Помнить надо адрес, а не команду.

У ставщика три режима, и режим — ответ на вопрос «чей это проект»:

| команда | когда | что кладёт |
|---|---|---|
| `node install.mjs .` | **новый сайт**, папка пустая | всё: `CLAUDE.md`, шкалы, правила, все скиллы, проверки, хуки, рабочий процесс CI |
| `node install.mjs --update .` | сайт, где набор **уже стоит** | проверки и скиллы; базы храповиков, `CLAUDE.md`, правила и шкалы проекта не трогает |
| `node install.mjs --audit .` | **чужой готовый сайт** — проверить, а не переделать | только проверки, свои четыре скилла и `kit.config.json`; ничего проектного не пишет, хуков не вешает |

Без ключа в папку, где уже есть свой `CLAUDE.md`, свои `docs/` или `styles/`,
ставщик **отказывает**, а не затирает (`docs/rules.md`, И169). Затереть можно
только словом `--force`.

### `kit.config.json` — где лежит проект и как названы его шкалы

Набор ищет код в `app/`, `components/`, `lib/`, стили в `styles/`, шкалы
`--fs-*`, `--sp-*`, `--layer-*` и три шва `1080 · 820 · 560`. У чужого проекта
всё это своё: `src/app`, `packages/ui`, `--text-*`, `--space-*`, один шов на
860. Раньше проверки помнили пути рукой — и на таком проекте молча зеленели:
папок «нет», значит и нарушений «нет» (И168). Теперь всё это — один файл в
корне проекта; ставщик в режиме `--audit` кладёт его со значениями набора,
чтобы было что править:

```json
{
  "code": ["src/app", "src/components", "src/lib"],
  "pages": "src/app",
  "styles": ["src", "../../packages/ui/src"],
  "lib": "src/lib",
  "tokens": "../../packages/ui/src/tokens/index.css",
  "base": "src/app/globals.css",
  "primitives": null,
  "scale": { "font": "text", "space": "space", "layer": "layer" },
  "breakpoints": [860],
  "aliases": { "@shop/ui/control.css": "../../packages/ui/src/components/Control/Control.module.css" }
}
```

Пишутся только поля, которые отличаются; `null` у файла — «его нет, и ворота
о нём молчат». Пороги правил (8% между ступенями, 500ms движения, 44px под
палец) в конфиг не выносятся нарочно: это закон набора, а не свойство проекта.
Полный список полей и значения по умолчанию — в шапке `tools/kit-config.mjs`.

**Клонировать этот репозиторий как папку нового сайта нельзя.**
`git clone <адрес> мой-новый-сайт` даст папку, чей `origin` — набор:
коммиты сайта поедут в набор, а следующее обновление набора встретит проект
конфликтом. Набор — слой поверх проекта, а не заготовка проекта.
`install.mjs` раскладывает файлы внутрь, оставляя историю набора в наборе.

`.git` в конце адреса необязателен: GitHub понимает оба написания.

## Палитра — как она работает

Цвет — первое, что заказчик видит, и первое, что рассыпается, когда числа
ставят рукой. Поэтому в наборе цвет не выбирают поштучно: заказчик называет
краски, а строитель считает всё остальное и меряет. Что и сколько — из кода,
не из памяти (собирает `check:rules`, отставшая таблица — красная сборка):

<!-- families:palette -->
| Факт | Значение | Откуда |
| --- | --- | --- |
| краски, которые называет заказчик, на тему | 3: paper, ink, accent; по желанию — error, sale, warn, ok, info | `templates/palette-starter.json`, `tools/palette.mjs` |
| семей смысла | 7: нейтраль, марка, красный «нет в наличии», плашка скидки, оранжевый «мало осталось», зелёный «в наличии», синий «просто сведение» | `tools/palette.mjs`, STATUS |
| переменных выпускается на тему | 49 | `roles()` в `tools/palette.mjs` |
| наборов-образцов | 7: Аптека · Олива · Мек остров · Тёплый лист · Ледяной шалфей · Аптечный синий · Латунь на угле | `templates/palette.json` |
| на сайте сейчас | Латунь на угле | `styles/palette.json` |
| команды | `palette` · `check:palette` · `palette:stand` · `palette:sheet` · `palette:builder` | `scripts.mjs` |
<!-- /families:palette -->

Порядок — десять шагов закона скилла `palette`: спросить краски → проверить
их до построения → выпустить (`npm run palette`) → замерить
(`npm run check:palette`) → раздать роли в `styles/tokens.css` → пройти
тёмную тему → показать глазами (стенд, лист, строитель) → записать и увезти
(`node install.mjs --palette "Имя" ../сайт`). Подключать `styles/palette.css`
**до** `styles/tokens.css`. Несколько наборов в одном файле — первый встаёт
на корень, остальные под `[data-palette="имя"]`.

## Откуда родом правила

Половина набора не выдумана здесь — она взята у других и названа своими
словами. Источники, чтобы это было сказано прямо:

* [Every Layout](https://every-layout.dev) — Хейдон Пикеринг и Энди Белл:
  идея примитива раскладки и словарь `stack`, `cluster`, `switcher`,
  `rail` (у них `Reel`), мера набора (у них `Center`). Реализация в
  наборе своя, от токенов; `lede` и `pinned` — свои.
* [Utopia](https://utopia.fyi) — Джеймс Гилхэд и Трис Мадфорд: метод
  текучей шкалы `clamp(мин, наклон, макс)` с прямой между двумя опорными
  ширинами. Числа в `tokens.css` свои, способ — их.
* [WCAG 2.2](https://www.w3.org/TR/WCAG22/) — цель нажатия 44×44 (2.5.5) и
  24×24 (2.5.8), останавливаемое движение (2.2.2), пороги контраста (1.4.3).
* [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines)
  (Vercel) — предсдаточный чеклист. Он вычитывается перед сдачей, а не
  копируется: список живёт у авторов и меняется.
* [ui-ux-pro-max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)
  (MIT) — половина проверок ремесла, но только измеримое.

У чужих скиллов в `.claude/skills/` лицензии лежат рядом файлами
`LICENSE.*`.

**Чего в этих источниках нет.** Четыре запрета из десяти заведены дефектом
живого сайта: три брейкпоинта, потолок у `aspect-ratio`, потолок у
приклеенного, геометрия контрола от его высоты. Готовый список их не
содержит — такое видно на странице, а не в правиле. Поэтому и весь смысл
набора не в списке правил, а в проверках: список, лежащий рядом, вёрстку не
меняет, а проверка, которая валит сборку, — меняет.

## Обновить набор в проекте, который его уже поставил

```
git clone --depth 1 https://github.com/IgorAIdev/MySkilforCBDSiteBuilding.git /tmp/kit && node /tmp/kit/install.mjs --update . && rm -rf /tmp/kit
```

`--update` обновляет проверки и скиллы и **не трогает** базы храповиков,
`CLAUDE.md`, `docs/`, `styles/` и рабочий процесс проекта: это его, а не
набора. До этого ключа обновление перезаписывало базы нулями — долг проекта
оказывался «прощён», — а переносимый `CLAUDE.md` со строкой
`0 · Основание` ложился поверх проектного (И169).

## Где источник

С 19.09.2026 источник — **этот репозиторий**. cbdin.bg закончен как
источник: он переехал в монорепозиторий `CBD_ecommerce_eu` (`apps/cbdin`),
набор оттуда снят решением владельца, а всё накопленное там перед переездом
лежит здесь. Проекты — потребители: правка, нужная набору, делается здесь и
приходит в проект через `--update`.

Обратный путь остался на случай, когда правка инструмента родилась в
проекте: `node tools/kit.mjs путь/к/клону/этого/репозитория` соберёт набор
из проекта в клон, не затирая здешние `README.md` и базу вёрстки, — дальше
ветка и PR сюда.

**У набора всегда ровно один источник.** Правка, сделанная в потребителе и
не вернувшаяся в источник, — вторая расходящаяся копия, то есть ровно та
болезнь, от которой набор и лечит.

## Набор проверяется собой

`.github/workflows/kit.yml` гоняет на каждом PR сюда: `check:rules` (замок
«проверка ↔ правило»), `check:css`, `check:code`, `check:port` на самом
наборе, тест-образец и самопроверку ставщика (`selftest/`): новый сайт,
обновление, аудит чужого — и что он при этом не трогает. Заготовка CI для
проектов лежит в `templates/check.yml`, а не в `.github/workflows/` набора:
там её исполнял бы GitHub на самом наборе и падал на `npm ci` (И170).

База вёрстки набора — не нули: у собственных `styles/` набора есть долг
(`twiceDrawn` 2, `tapGrows` 1, `deadDress` 1, `plateGap` 1), и он записан,
а не спрятан. Новый сайт получает эту базу и с первого `check:css` зелёный;
чинится долг здесь, и с каждой починкой база опускается (И171).

## Что доставить руками

Скрипты в `package.json` дописал ставщик. Осталось одно:

```
npm i -D sharp wait-on && npx playwright install chromium
```

Проверкам по странице нужен поднятый сайт и сервер, умеющий **чистые
адреса** (`/product` → `product.html`). Он в наборе — `tools/serve.mjs`,
без зависимостей, повторяет боевой нгинкс. Чужие не годятся, и это проверено
дважды: `python3 -m http.server` отдаёт листинг каталога вместо страницы, а
`serve` из npm уводит `/bg` на `/bg/index.html`, которого у статического
экспорта нет, и вдобавок умирает от нехватки дескрипторов посреди прогона —
после чего проверка мерит недогруженные страницы и показывает находки,
которых нет.

```
npm run build && npm run serve
```

Путь к Playwright задаётся через `PLAYWRIGHT=`, адрес сайта — через `SITE=`.

## Что работает без вашей памяти

Два файла, и в этом весь смысл набора.

**`CLAUDE.md`** читается раньше кода каждой сессией агента. Не надо помнить
правила и не надо их пересказывать.

**`.github/workflows/check.yml`** валит сборку сам. Проверка, которую надо
не забыть запустить, будет забыта; проверка, которая валит сборку, — нет.
