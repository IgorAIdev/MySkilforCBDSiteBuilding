# Элементы на выбор

Органы управления, которые прислал заказчик — скриншотом, кодом или
ссылкой, — нарисованные, но ещё не выбранные: кнопки, знаки, поля, вкладки,
меню, карточки, сообщения.
Живут в наборе, а не в сайте: ни сайт, ни панель вида эту папку не читают.

## Как идёт работа

1. Заказчик присылает элемент.
2. Элемент получает папку `NN-имя/`: источник (`source.png`, `source.html`)
   и отрисовка `element.html` — одна страница без сборщика.
3. Отрисовка сразу разобрана до базовой: лишнее — тень, размытие, заливка
   фоном при наведении — снимается сразу и называется в `снято`.
4. И сразу приводится к единой форме: стоит на основе `base.css` (числа
   набора), отличается только её атрибутами, значки — из листа набора,
   краски — роли палитры набора. Движение источника — только названное
   заказчиком; совпавший после разбора — вторым источником к уже лежащему.
   Чего основа не умеет — дописывается в основу; что поменялось — в
   `приведено`.
5. Состояния продумываются сразу: наведение, нажатие, фокус — по правилу
   набора (И273: «меняется только цвет, уменьшается размер при нажатии,
   кнопка смещается чуть»). На странице они стоят застывшими рядом с живым
   элементом — видно без мыши, с телефона.
   У поля нажатия нет — в него пишут: нажатие ставит курсор, это фокус;
   вместо нажатия продумано и показано заполненное (И350).
6. Запись в `elements.json`: имя, род, семья стиля, метки из словаря,
   состояния, что снято. Имя даётся сразу при приёме и не повторяется;
   номер папки — постоянный адрес, по нему заказчик пишет «33». Элементы
   одной семьи подходят друг к другу и предлагаются вместе.
7. `node tools/elements.mjs` проверяет метки и собирает `index.html`:
   сверху — оглавление по роду («кнопка — 02, 03…», номер ведёт к
   элементу), ниже — семьи стиля. Сессии ищут командой
   `node tools/elements.mjs --list поле` — номер · имя · семья (И351).
8. Сделанное вливается в панель вида вариантом группы, у которой есть место
   на витрине: кнопка — вариантом оси `styles/buttons.json`, отметка меню,
   поле, карточка — значениями ролей или вариантом файла (`look-panel/PANEL.md`).
   Заказчик выбирает на живой витрине; сайт получает одно опубликованное
   значение. Элемент без места на витрине остаётся в каталоге (И356).

## Что внутри

- `elements.json` — каталог: словарь меток, характеры витрины, семьи стиля,
  элементы;
- `base.css` — основа: одна форма для всех элементов, числа набора;
- `palettes.css` — палитра сайта и образцы набора, выпущены строителем
  палитры из `styles/palette.json` и `templates/palette.json`;
- `stage.js` — сцена страниц папки: палитра и тема из адреса, значки листа
  набора вставлены в страницу; собран из `styles/icons.svg`;
- `cbdin-sources/` — исходники cbdin.bg: снимки дизайн-системы, модуль
  знака «куда ведёт», лист значков;
- `index.html` — страница выбора, собрана из каталога, руками не правится;
- `NN-имя/` — источник и отрисовка каждого элемента.
